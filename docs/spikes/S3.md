# Spike S3 — ENSv2 register, ownerOf, transfer, per-record writes

Decision: **FALLBACK (b)**. Identity calls were compiled and executed against `contracts/lib/contracts-v2`. Per-record text protection was not. `com.rival.*` lives in `RivalNames` storage. `isListed` still reads `ownerOf` and fails closed, so this is not fallback (a).

## What was confirmed in the pinned source

`IStandardRegistry.register` in `contracts/lib/contracts-v2` is:

```solidity
function register(
    string calldata label,
    address owner,
    IRegistry registry,
    address resolver,
    uint256 roleBitmap,
    uint64 expiry
) external returns (uint256 tokenId);
```

`renew(uint256 anyId, uint64 newExpiry)` sets an absolute expiry and reverts `CannotReduceExpiry` if the new value is earlier. `unregister(uint256 anyId)` reverts `LabelExpired` when `block.timestamp >= expiry`. `ownerOf` returns `address(0)` for an expired or version-mismatched id. `ROLE_CAN_TRANSFER_ADMIN` is `(1 << 28) << 128`. A transfer without that role reverts `TransferDisallowed`. Granting or revoking a role regenerates the token id.

`PermissionedResolver.authorizeTextRoles` can grant `ROLE_SET_TEXT` on one text key. That is real per-record ACL, and it is separate from the registry `roleBitmap`. It could not be executed here.

## Executed results

Against `PermissionedRegistry`:

- `issue("atlas", solver, now + 30 days)` succeeded. `ownerOf(tokenId) == solver`. The solver's role bitmap was `0`. `hasRoles(ROLE_CAN_TRANSFER_ADMIN)` was false.
- `safeTransferFrom` by the solver reverted `TransferDisallowed`.
- A second `issue` of `atlas` reverted `LabelAlreadyRegistered`.
- `renew` to a later timestamp stuck. A renew to an earlier timestamp did not shorten it (`max` with the current expiry).
- `unregister` cleared the name (`ownerOf == 0`). A later `issue` of the same label returned a different token id.
- At the expiry timestamp, `ownerOf` returned `address(0)` and `unregister` reverted `LabelExpired`. `renew` from `RivalNames` revived the same token (`ownerOf == solver` again), because root `ROLE_RENEW` satisfies `_canRevive`.
- `grantRoles(..., ROLE_RENEW, solver)` after issue changed the token id. `ownerOf` on the id stored at issue returned `address(0)`. `tokenIdOf` still returned the old id. `RivalNames` does not update it.

`syncRecords` wrote `protocolRecord` only. No `setText` call. A mock-only success was not used to claim primary.

## Why not primary

Primary would mean register, `ownerOf`, and unregister on the pinned types, **and** per-record protection so a solver can edit `description` / `url` / agent keys and cannot edit `com.rival.*`. The first half ran. The second half cannot be compiled in this checkout, and the registry role bitmap cannot express it. Fallback (b) in FR-ENS-06 puts `com.rival.*` off the solver's own name. The child name `stats.<label>.solvers.<parent>.eth` was not used: it still needs the resolver and a parent `.eth`. The four values are stored on `RivalNames` and exposed as `protocolRecord`. They are authoritative. They are not ENS text.

## H-006

Skip H-006. Do not register `rival.eth` and do not spend ETH. The contracts issue, gate, renew, and unregister on a `PermissionedRegistry` we deploy ourselves, which M-017 can do without a purchased parent. Buying `rival.eth` only matters later, if the demo must resolve `solvers.rival.eth` in the Sepolia ENS app. It would not turn on `com.rival.*` text records: those stay in `RivalNames` until `ens-contracts` is checked out and `PermissionedResolver` per-key roles are actually granted. A lapsed name also cannot `unregister` until `renew` revives it, so a parent registration does not fix deposit reclaim after expiry.
